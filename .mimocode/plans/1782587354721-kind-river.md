# Plan: Improve Dynamic World Classification Accuracy

## Key Findings from Research

### Current Issues (from exploration)
1. **Wrong S2 data source**: We use `S2_HARMONIZED` (surface reflectance/L2A), but DW model was trained on `COPERNICUS/S2` (L1C/top-of-atmosphere). Normalization constants are calibrated for L1C.
2. **Unnecessary Gaussian blur**: Smears class boundaries, makes results look "laxer" than official DW.
3. **RGB upload path is fundamentally flawed**: Model trained on 9 real Sentinel-2 bands can't work well with 3 fabricated RGB-derived bands.
4. **No cloud masking**: DW docs say they mask clouds using S2 Cloud Probability, Cloud Displacement Index, and Directional Distance Transform.

## Implementation Plan (ordered by impact)

### Phase 1: Fix Current Pipeline (highest impact, lowest effort)

**1a. Fix S2 data source — use L1C instead of L2A**

- File: `ee_fetcher.py`
- Change: `COPERNICUS/S2_HARMONIZED` → `COPERNICUS/S2` (with fallback to HARMONIZED if S2 fails)
- Why: DW normalization constants were calibrated on L1C reflectance values. L2A surface reflectance has different distribution.

**1b. Remove Gaussian blur**

- File: `dw_processor.py`
- Change: Remove the Gaussian blur post-processing entirely
- Why: Official DW outputs raw per-pixel softmax. The blur smears boundaries.

**1c. Add confidence thresholding**

- File: `dw_processor.py`
- Change: After softmax, mask out pixels where max confidence < threshold (e.g., 0.5)
- Why: DW docs explicitly recommend this. Low-confidence pixels are noise.

**1d. Fix cloud masking in EE fetcher**

- File: `ee_fetcher.py`
- Change: Add cloud mask using `COPERNICUS/S2_CLOUD_PROBABILITY` collection. Mask pixels where cloud probability > 35% (matching DW's threshold).
- Why: DW masks clouds and cloud shadows before classification.

### Phase 2: Temporal Compositing (medium impact)

**2a. Multi-date fetching**

- File: `ee_fetcher.py`
- Change: Fetch multiple Sentinel-2 images for a date range, apply temporal compositing:
  - **Median composite**: Robust to outliers, good for stable land cover
  - **Least-cloudy**: Already implemented, but improve cloud filtering
  - **Per-pixel max confidence**: Run DW on each image, take the class with highest confidence per pixel
- Why: Single images may have artifacts (clouds, haze, shadows). Temporal compositing produces cleaner results.

**2b. Temporal voting ensemble**

- File: `dw_processor.py`
- Change: Run DW model on N temporal images, take majority vote per pixel
- Why: Reduces noise and increases confidence in stable land cover classes

### Phase 3: Second Model — Prithvi-EO-2.0 (high impact, medium effort)

**3a. Integrate Prithvi-EO-2.0-100M-TL**

- Files: New file `prithvi_processor.py`, update `app.py`
- Change: Add Prithvi-EO-2.0 as a second classifier using TerraTorch
  - Uses 6 HLS bands: Blue, Green, Red, Narrow NIR, SWIR1, SWIR2
  - Supports temporal sequences (multi-date input)
  - Has location/time embeddings for better context
- Why: Foundation model pretrained on 4.2M global samples, fine-tuned for land cover. Outperforms single-task models.

**3b. Model ensemble — combine DW + Prithvi**

- File: `dw_processor.py` or new `ensemble.py`
- Change: Run both models, combine predictions:
  - **Weighted average**: Weight by per-pixel confidence
  - **Voting**: Take majority class
  - **Cascaded**: Use DW for high-confidence regions, Prithvi for ambiguous areas
- Why: Ensemble of complementary models typically outperforms any single model.

### Phase 4: CRF Post-Processing (low impact, medium effort)

**4a. Add CRF smoothing**

- File: `dw_processor.py`
- Change: Apply Conditional Random Field (using `pydensecrf`) to refine boundaries
  - Use RGB image as appearance feature
  - Use classification as unary potential
  - Smooth with spatial coherence
- Why: CRF respects image edges while enforcing spatial consistency. Standard in segmentation pipelines.
